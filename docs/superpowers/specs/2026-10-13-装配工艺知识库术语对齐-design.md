# 装配工艺知识库软件 —— 术语对齐与知识检索功能设计

> **文档版本**: v1.0
> **编制日期**: 2026-10-13
> **适用系统**: 装配工艺知识库软件（系统代号 OCR-Benti）
> **文档性质**: 面向项目验收的界面术语对齐与功能补齐设计

---

## 1. 背景与目标

### 1.1 背景

本项目现有系统的界面术语是**按业务需求演化的**：界面主标题为"本体建模系统"，导航与操作文案统一使用"本体"口径（本体推理、新增本体、子本体、本体概念数等）。

而项目验收合同对交付物的描述为：

> 研发装配工艺知识库软件工具 1 项，具备**知识建模、知识组织、知识检索**等功能。

界面术语与合同验收口径不一致，会给验收带来直接风险：验收专家对照合同功能项检查系统时，无法在界面上找到"知识建模 / 知识组织 / 知识检索"三个功能入口。

### 1.2 目标

1. **命名统一**：软件对外名称统一为"装配工艺知识库软件"，消除"本体软件"类表述。
2. **功能术语对齐**：将"知识建模、知识组织、知识检索"按语义相似度映射到系统现有能力，并在界面上形成清晰可见的功能入口。
3. **功能补齐**：系统当前**完全不具备知识检索能力**（后端无任何检索 API，前端无检索入口），需新增一个真实可用的知识检索功能，使"具备知识检索功能"这一验收项经得起现场演示。
4. **不破坏现有功能**：所有改动限于用户可见文案与新增功能，不改动代码内部标识符、数据模型与 API 契约。

### 1.3 非目标

- 不改动后端数据模型（`OntologyNode` / `OntologyEdge` / `GraphState`）。
- 不改动现有 API 路径与请求/响应契约。
- 不改动代码内部标识符（变量名、函数名、事件名、localStorage 键、包名）。
- 不重构现有视角组件的数据流与布局算法。

## 4. 新增知识检索功能

### 4.1 后端接口

新增文件 `backend/app/routers/knowledge.py`，并在 `backend/app/main.py` 中注册路由。

```
GET /api/knowledge/search
```

**请求参数**

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `project_id` | str | 是 | — | 项目 ID |
| `q` | str | 是 | — | 检索关键词（长度 ≥ 1） |
| `scope` | str | 否 | `all` | 检索范围：`all`／`concept`／`attribute`／`relation`／`source` |
| `limit` | int | 否 | 50 | 单类结果上限（1~200） |

**检索逻辑**（大小写不敏感的包含匹配）

- `concept`：概念的 `name` 命中关键词。
- `attribute`：概念的 `attributes` 中任一 `key` 或 `value` 命中关键词。
- `relation`：关系边的 `relation` 名称命中关键词。
- `source`：概念或关系边的 `origin`（数据来源标识，如 `excel:文件名.xlsx`、`dameng`）命中关键词。
- `all`：上述四类全部检索。

**响应结构**

```json
{
  "query": "刀具",
  "total": 3,
  "concepts": [
    {
      "id": "uuid",
      "name": "刀具材料",
      "match_field": "name | attribute | source",
      "match_snippet": "命中片段",
      "parent_path": "机床 / 主轴 / ",
      "origin": "manual",
      "attributes": [{"key": "硬度", "value": "HRC60"}]
    }
  ],
  "relations": [
    {
      "id": "uuid",
      "source_id": "uuid",
      "source_name": "切削参数",
      "target_id": "uuid",
      "target_name": "表面粗糙度",
      "relation": "影响",
      "match_field": "relation | source",
      "origin": "manual"
    }
  ]
}
```

**实现要点**

- 数据加载复用 `main.py` 中已有的项目数据读取函数，采用**函数内延迟导入**（`from app.main import ...`）以避免路由模块与 `main.py` 之间的循环导入。
- 响应模型（Pydantic）定义在 `knowledge.py` 内部，不污染 `main.py` 的模型定义。
- 术语提示：接口路径与响应字段沿用中性的 `knowledge` 命名，不引入 `ontology` 字样。
- **全空白查询**（如 `q=" "`，strip 后为空串）必须提前返回空结果集 —— 否则 `"" in 任意字符串` 恒为真，会误命中全部数据。
- **项目不存在**时返回空结果集（HTTP 200），不抛异常；这是有意的容错行为。
- **字段语义**：`total` 是本次**实际返回的条数**（受 `limit` 截断），非命中总数；`match_snippet` 是命中字段的**完整原值**，非上下文片段。
- **字段词汇映射**：请求参数 `scope` 使用 `concept`，响应字段 `match_field` 对应返回 `name` —— 二者指同一维度，前端需按此映射展示标签。

### 4.2 前端交互

在 `App.vue` 工作台区新增 `retrieval` 标签面板，包含：

1. **检索输入区**
   - 关键词输入框（占位文案："输入概念名称、属性或关系关键词"），支持回车触发检索。
   - 检索范围多选（复选框组）：概念名称 / 概念属性 / 关系 / 数据来源，默认全选。
   - 「开始检索」按钮；检索中显示加载态。
2. **结果区**
   - 概览行："共命中 N 条结果"。
   - **知识概念**分组：每条显示概念名称、命中字段标签、命中片段、父级路径、数据来源。
   - **知识关系**分组：每条显示 `源概念 —关系→ 目标概念`、命中字段标签、数据来源。
   - 空态文案："未找到匹配的知识，请尝试其他关键词"。
3. **结果定位**
   - 点击某条**概念**结果 → 切换到「知识建模」视角，画布平移使该概念居中，并高亮该概念。
   - 点击某条**关系**结果 → 切换到「知识建模」视角，高亮该关系的两个端点概念及其连线。

### 4.3 定位与高亮实现

复用系统已有的画布状态机制，不引入新概念：

- 已有 `highlightedNodeIds` / `highlightedEdgeIds` / `highlightEnabled` 用于高亮（当前由贝叶斯分析使用），检索定位直接复用。
- 新增 `focusNodeOnCanvas(nodeId)` 函数：根据节点坐标与画布可视区域尺寸计算 `viewOffset`，使节点水平垂直居中；**缩放比例保持不变**（仅平移，不复位 `zoom`），避免用户视野突变。
- 切换视角通过设置 `currentPerspective.value = 'process'` 完成。

### 4.4 前端组件划分

检索功能拆为**两个职责单元**，避免继续膨胀本已约 6000 行的 `App.vue`：

| 单元 | 职责 | 不负责 |
|---|---|---|
| `KnowledgeSearchPanel.vue`（新建） | 关键词输入、范围勾选、发起 `/api/knowledge/search` 请求、渲染结果列表；内部自持 `query` / `selectedScopes` / `results` / `loading` / `error` 状态 | 不接触画布、不知道视角切换 |
| `App.vue`（改造） | 挂载面板；接收 `locate-concept` / `locate-relation` 事件；切换视角、平移画布居中、设置高亮 | 不实现检索 UI |

`App.vue` 侧新增函数：`switchWorkbench(tab)`、`highlightNodes(nodeIds, edgeIds)`、`focusNodeOnCanvas(nodeId)`、`onLocateConcept(nodeId)`、`onLocateRelation(edgeId)`。

## 9. 风险与注意事项

| 风险 | 说明 | 应对 |
|---|---|---|
| 同名"知识组织"造成困惑 | 工作台与视角各有一个"知识组织"，分属操作入口与视图 | 通过 3.3 节联动规则使其互相跳转，语义自洽 |
| 后端循环导入 | `knowledge.py` 需读取 `main.py` 的项目数据加载函数 | 采用函数内延迟导入，不做模块级导入 |
| 检索性能 | 项目数据为 JSON 文件全量载入内存，规模有限 | 单次检索为内存内字符串匹配，性能无风险 |
| 构建产物未同步 | `frontend/dist/` 内仍含旧文案 | 改动后执行 `npm run build` 重新构建 |
